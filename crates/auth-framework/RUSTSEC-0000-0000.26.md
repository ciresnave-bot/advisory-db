# `/oauth/revoke` did not authenticate its caller and stored a marker for any string

`POST /oauth/revoke` took only `{token, token_type_hint}`. For any string up to 8 KiB it stored a 30-day revocation marker (`oauth2_revoked_token:<string>`), whether or not the string was a token this server had issued, so anonymous requests could grow the revocation store without bound: 200 junk strings left 200 stored markers. It also let anyone who held a refresh token revoke it without authenticating as the client it was issued to, which RFC 7009 section 2.1 requires.

It could not revoke a token the caller does not hold (the token value is the lookup key), so it was not a way to log other people out.

The fixed versions act only on tokens this server issued (anything else is a successful no-op that stores nothing, RFC 7009 section 2.2), and a token issued to a client is revoked only after that client authenticates (HTTP Basic or `client_id`/`client_secret` in the body; a public client names itself). Until you can upgrade, rate-limit or block `/oauth/revoke` at your edge.
