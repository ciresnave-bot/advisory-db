# OAuth2 client secrets were stored in plaintext by dynamic client registration

`register_client` (`POST /oauth/register`) wrote the new client record, including `client_secret` as plain text, to the key value store under `oauth2_client:{client_id}`, and the token, introspection and revocation endpoints compared a presented secret with that stored plain text. Anyone able to read the storage backend (a database dump, a backup, a replica or an over-broad read role) could read every registered client's secret and authenticate as that client.

Registering a client needs a Bearer token with the `admin` role or the Initial Access Token, and no remote way to read the stored value was found; the exposure is the stored secrets themselves.

The fixed versions store only an Argon2id hash (`client_secret_hash`) and return the secret once at registration. A record that still holds a plain `client_secret` keeps working, and the first successful authentication of that client rewrites it with the hash. A plain secret therefore stays in storage until its client next authenticates: rotate the secrets of clients that rarely do, and treat backups taken before the upgrade as holding the plain secrets.
