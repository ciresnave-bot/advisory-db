# Token introspection accepted an empty client secret for clients registered without one

`/oauth/introspect` read the stored client secret as an empty string when a client record had no secret, an empty one or a non-string one, and compared the presented secret with it. A client registered without a secret therefore authenticated with an empty presented secret (HTTP Basic `client_id:` or a POST body with an empty `client_secret`), although RFC 7662 section 2.1 requires the endpoint to demand authorization.

Clients created through `POST /oauth/register` always receive a secret and are not affected; only secret-less (public) clients written into storage by an operator were. The caller also needs the token it asks about, so what it learns is the state and claims of a token it already holds.

The fixed versions refuse such a client with `invalid_client` (HTTP 401). A public client that relied on calling introspection must be given a secret.
