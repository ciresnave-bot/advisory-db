# The OAuth2 authorization_code grant did not check the client secret

`POST /oauth/token` with `grant_type=authorization_code` only checked that the request carried some `client_secret`; it never compared it with the registered secret of a confidential client. Anyone holding a valid authorization code for a confidential client and that client's `client_id` could redeem the code for access and refresh tokens, supplying any secret string. The code is single use and bound to its redirect URI (and to its PKCE challenge, when one was used), so the attacker needs the code itself, for example from a redirect or a log.

The fixed versions authenticate the client before the code is read: a confidential client must present its registered secret, a failed authentication neither reveals nor consumes the code, and a code issued to another client is refused and left intact. Public clients are unchanged and must use PKCE.

If you cannot upgrade, require PKCE for every client: a code bound to a PKCE challenge cannot be redeemed without its verifier.
