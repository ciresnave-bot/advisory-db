# Token introspection reported any client's token to every authenticated client

`POST /oauth/introspect` and `TokenIntrospectionService::introspect_token` authenticated the caller but never compared it with the client a token was issued to (RFC 7662 section 4). Any authenticated client that held another client's token (or a valid token id) learned whether it was active and its subject, scope, `jti`, expiry and client. The library service's opaque-token path also reported no client at all. No token value is disclosed and nothing can be changed; the caller needs a registered client's credentials and the token it asks about.

The HTTP route exists from 0.5.0-rc18 and `TokenIntrospectionService` (a public library type that the framework's router does not mount) from 0.4.0; on the 0.5 line the route's own JWTs carry no client claim, so there the library service is the reachable part.

The fixed versions report a token issued to a client only to that client; any other authenticated client gets `active: false` and nothing else. A token that carries no client (a first-party token) is still introspectable by any authenticated client: the framework has no resource-server role yet to restrict it to. The 0.4.x line has no fixed release at the time of writing; restrict `/oauth/introspect` to resource servers and do not register untrusted clients until you can upgrade.
